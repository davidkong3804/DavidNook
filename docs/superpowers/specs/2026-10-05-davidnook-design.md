# DavidNook 設計（2026-10-05，使用者已於對話中核准）

## 目標
macOS 瀏海工具，完全本機、無授權伺服器、永不過期。取代已失效的 NotchNook（專有軟體，不得複製其程式碼/素材/字串；只參考「行為」）。
只做：瀏海外觀與互動、剪貼簿歷史、動態歌詞（繁體中文正確性最優先）、播放控制（使用者所謂「歌詞點播」＝播放/暫停/上一首/下一首＋正確歌詞，不需獨立搜尋功能）。
不做：AI、帳號、雲端同步、遙測、自動更新。

## 架構
- `Packages/DavidNookCore`（Swift package，純邏輯，`swift test` 可跑）：LRC 解析與時間軸插值、歌詞候選挑選、簡/繁判斷與轉換、剪貼簿儲存規則。
- App 本體：fork 的 boring.notch，改名 DavidNook（bundle id、圖示、zh-Hant 為主要語言）。裁掉 Sparkle、NotificationWatcher、OTP 偵測、音訊擷取、鏡子等非指定模組與多餘權限；移除 `NSAllowsArbitraryLoads`、`network.server`。
- Now Playing：沿用 mediaremote-adapter，但由上游原始碼（v0.7.7）自行重建，不採用 repo 內預編譯二進位；啟動自檢（`test`），失敗退回 Music.app 備援。位置＝`elapsedTime + (now − timestamp) × playbackRate` 插值，不靠輪詢。

## 歌詞管線
1. 查詢：`/api/get`（原樣→s2t→t2s 三種寫法，帶 duration，404 才換下一種）＋ `/api/search`；**get 的單筆不直接採用，併入 search 候選池（id 去重）後統一交給 Picker 做多版本共識排序**（詳見「歌詞挑選共識化與殘留簡體修正」）。必須自報 User-Agent；遵守 429 `Retry-After`；503 重試。
2. 過濾：instrumental、無 syncedLyrics、duration 差 >2s 皆剔除。排序：duration 差 → 原生繁體優先 → 首句時間貼近候選中位數 → 簡體殘留字數較少 → id。
3. 清理：剝除檔頭中繼行（詞/曲/編曲/監製/OP/SP、`X - Y` 行，僅前 10 行且 <25s）、`[ti:]` 等 ID tag、尾端空時間戳行；處理 CRLF 與 `<mm:ss.xxx>` 行內標籤。
4. 簡繁判斷：統計全文「簡體專有字」與「繁體專有字」比例（排除 `麽`、`着`、`里后干发面台群於`）；無專有字→中性不轉；繁體專有字 ≤3%→簡體→轉換；簡體專有字 ≤3%→繁體→不轉（僅 t2tw 變體正規化，但行內殘留的簡體專有字會逐行修復）；其他→混合，逐行判斷。標題不可靠，用全文。歌名/歌手名不轉換顯示。
5. 轉換：先套覆寫表（如 发如雪→髮如雪、发端→髮端），再 OpenCC；最後一步套「里→裡」詞級規則（里前一字不在前綴排除集、後一字不在後綴排除集、不屬整詞保護 → 「裡」；細節見「里→裡 詞級規則」）。原生繁體路徑另先套用覆寫表中「鍵含簡體字形」的條目（修殘留的「重复」等）。
6. 偏移：以 title+artist+duration 為鍵，依曲目記住。
7. 顯示：約 5 行，當前行高亮，上下淡出。

## 剪貼簿
文字/圖片/檔案路徑；搜尋、釘選、暫停記錄、筆數與保留時間可設。略過 `org.nspasteboard.ConcealedType/TransientType/AutoGeneratedType`。只存本機（Application Support，0600 權限），不記錄內容到 log，提供「清除全部」。點選後寫回剪貼簿；已授權輔助使用時才自動貼上。

M3 實作（App 端）：
- `ClipboardService`（app target）持有 Core 的 `ClipboardStore`＋`ClipboardMonitor`：存放於沙盒內 `Application Support/DavidNook/Clipboard`（目錄 0700、檔案 0600、**目錄已排除於 Time Machine 備份**；索引 `index.json`＋`<hash>.<副檔名>` 圖片檔；損毀索引的隔離檔 `index.json.corrupt` 最長保留 24 小時，「清除未釘選」「清除全部」都會刪除）。設定（記錄開關、暫停、筆數上限、保留天數）即時套用；啟動時、設定變更時與每 5 分鐘 prune（同時重試上次失敗的索引寫入；連續失敗會提示「無法寫入剪貼簿歷史，請檢查磁碟空間」一次）。暫停／恢復／權限變化的決策在 Core 的 `ClipboardRecordingPlanner`：任何恢復路徑都先 `syncBaseline`，暫停期間複製的內容恢復後不會被補記。預設：記錄開、未暫停、100 筆、保留 30 天、自動貼上關。單項大小上限用 Core 預設（文字 1MB／圖片 20MB），不開放設定。
- UI：`DavidNookUI.ClipboardPanelView`（資料驅動）＋Core 的 `ClipboardPanelModel`（選取、鍵盤導覽、空狀態；有測試）。縮圖由 `ClipboardThumbnailCache` 以 ImageIO `CGImageSourceCreateThumbnailAtIndex` 在背景產生（最長邊 96px、快取 120 張／8MB、來源上限 1 億像素），原圖不進入視圖狀態。
- 鍵盤（↑↓ Home End Enter ⌘⌫ ⌘P Esc）由 App 端以 `NSEvent` 區域監聽攔截，**輸入法組字中（`hasMarkedText`）一律放行**；分頁顯示期間才讓瀏海視窗可成為 key window（`wantsKeyForTextInput`），視窗為 key 時瀏海保持展開。
- 全域快捷鍵「開啟剪貼簿」預設不設定，由使用者在設定 → Shortcuts 指定。

## 已知風險／未驗證
- **（M1 實測教訓）ad-hoc 簽章＋Hardened Runtime＋「連結」內嵌 framework → 啟動即崩潰**：dyld 報 `mapping process and mapped file (non-platform) have different Team IDs`（library validation）。編譯成功完全看不出來，只有實際啟動才會發現。正解不是關 Hardened Runtime，而是 adapter framework 只「嵌入」不「連結」（adapter 官方設計本來就是由 perl 載入）；app 原始碼沒有任何 `import MediaRemoteAdapter`。M2 自行重建 adapter 時維持此做法。
- **這台機器沒有實體瀏海螢幕**（M4 Pro 桌機：ASUS 外接螢幕＋一個虛擬/次要顯示器，`safeAreaInsets.top` 皆為 0），「有瀏海螢幕」的行為無法在本機實測，只能靠無瀏海（浮動瀏海）路徑與程式碼閱讀。
- **（M2 實測／核對）adapter 預設輸出的 `timestamp` 是 UTC、秒級解析度的字串**（`yyyy-MM-dd'T'HH:mm:ss'Z'`，小數秒被截掉），拿來當錨點會讓歌詞最多差 1 秒；改用 `stream --micros`（`timestampEpochMicros`／`elapsedTimeMicros`／`durationMicros`）。欄位格式依上游 README 與原始碼 v0.7.7 核對，**未用真實播放驗證**（此刻沒有播放，adapter `get`／`stream` 皆為空）。
- **（M2 實測）app 被 SIGTERM（pkill）時 adapter 的 perl 子行程會變孤兒**並一直活著（沒有輸出就不會因 SIGPIPE 結束）；已改為 SIGTERM 走正常終止流程。SIGKILL／當機仍可能留下孤兒，下次有輸出時會自行結束。
- **（M2）「純音樂」狀態**：UI 元件支援，但 LRCLIB 管線目前無法區分「純音樂」與「找不到」（Picker 會剔除 instrumental 候選、`LyricsFetching` 只回 nil），所以 app 目前對純音樂顯示「這首歌沒有歌詞」。要顯示「純音樂」需要擴充 Core 的回傳型別。
- **（M2）專輯名不送 LRCLIB**（來源資料很髒，只會降低命中率），也與設定頁揭露文字（曲名、歌手與長度）一致。
- adapter 依賴 Apple 私有行為（/usr/bin/perl entitlement），Apple 可能封掉；已有自檢與備援設計。
- 真實 Apple Music 播放、播放控制、歌詞時間軸 vs 實際音訊：未驗證（需使用者播放歌曲）。
- 背景輪詢 NSPasteboard 在 macOS 27 是否觸發隱私提示：未驗證。
- ad-hoc 簽章每次重建 cdhash 會變，TCC 授權可能要重授。
- 同 duration 的不同 LRCLIB 版本時間軸可能差 10 秒以上（實測旅行的意義），靠中位數挑選＋手動偏移緩解。
- 「台→臺」「了解→瞭解」屬風格問題，目前不處理，待使用者回饋。
- **（M3）macOS 15.4+ 的「從其他 App 貼上」**：背景讀 `NSPasteboard.general` 內容會觸發系統提示。`ClipboardService` 以 `NSPasteboard.accessBehavior`（AppKit 標頭 `API_AVAILABLE(macos(15.4))`，Swift 名稱 `.default/.ask/.alwaysAllow/.alwaysDeny`；部署目標 14.0 以 `#available` 守護，更舊系統一律視為允許）判斷：`.ask`、`.alwaysDeny` 時停止輪詢讀取並顯示說明橫幅，避免反覆跳提示；`.default`（尚未觸發過提示）時照常監看，第一次讀取內容時系統會問一次，之後狀態變 `.ask`，面板就會請使用者改成「允許」。**未驗證**：`pasteboardItems`／`types`（只列型別）是否也會觸發提示、使用者改設定後 `accessBehavior` 的更新時機、真實複製時的提示行為。
- **（M3）設定窗格連結**：公開文件沒有「從其他 App 貼上」窗格的 URL（開發者回饋 FB17587724 仍是需求）。本機 Settings 的 `SecurityPrivacyExtension` 二進位內有 `Privacy_Pasteboard` 錨點（與 `Privacy_Camera` 等同格式；該擴充宣告 `allowsXAppleSystemPreferencesURLScheme`；窗格名稱 zh_TW 為「從其他App貼上」、en 為「Paste from Other Apps」），所以先開 `x-apple.systempreferences:com.apple.preference.security?Privacy_Pasteboard`，失敗再退回 `?Privacy`。屬未公開細節，**未實際開啟驗證**。
- **（M3）自動貼上（實驗性，預設關）**：App 是沙盒的。`AXIsProcessTrusted()` 屬輔助使用 TCC 服務，與 App Sandbox 不相容，所以改用 `CGPreflightPostEventAccess()` 檢查、設定頁按鈕才呼叫 `CGRequestPostEventAccess()`，授權後以 `CGEvent.post(tap: .cgSessionEventTap)` 送 ⌘V。依據是 Apple DTS 在開發者論壇的說明（thread 820594、708652：PostEvent 權限與沙盒相容，系統設定中顯示在「輔助使用」之下）；網路上另有文章主張沙盒內 `CGEvent.post` 一律被擋。兩種說法互相矛盾，且**未實測**（授權需使用者在系統設定操作，貼上也需要動到剪貼簿與前景 App），所以標示為「實驗性」。沒有新增任何 entitlement。送出 ⌘V 前一刻（延遲 180ms 之後）由 Core 的 `AutoPasteGate` 判斷：系統啟用安全輸入（`IsSecureEventInputEnabled()`，焦點在密碼欄）或最前景是 DavidNook 自己時不貼，內容仍留在剪貼簿，安全輸入時顯示短暫提示「已複製；目前焦點在安全輸入欄位，未自動貼上」。`IsSecureEventInputEnabled()` 在真實密碼欄的行為**未實測**（僅確認 Release 沙盒建置可編譯）。
- **（M3）未驗證**：真實剪貼簿端到端（複製→記錄→點選寫回→貼上）、瀏海視窗成為 key window 後搜尋欄的實機輸入與焦點歸還（含注音輸入法）、`⌘V` 自動貼上、多螢幕、精簡模式（沒有分頁列，剪貼簿不可達）。
- **（M3 教訓）**`ImageRenderer` 不會畫出 `ScrollView` 與 `TextField`（AppKit 後端）：快照以內部環境值 `clipboardStaticRender` 改用靜態列表與 `Text`；靜態列表要放在 `Color.clear.overlay` 內，否則 flexible frame 的最小高度來自子視圖，會把上方搜尋列擠出面板。快照測試曾因此一度渲染出錯位版面，只看像素斷言不夠，要逐張看圖。


## M4 實作筆記（繁中介面、設定整理、圖示、README、NOTICES）

### 在地化（步驟 1）
- **只保留 `en` 與 `zh-Hant`**：`boringNotch/Localizable.xcstrings` 原有 21 種語言（上游 Crowdin 的 de/fr/ja/ko…、`zh-Hans`、`zh-Hant-HK`、`en-GB` 等）已全數移除。理由：原始碼自 M1 起大幅改動（Shelf、HUD、行事曆、Sparkle 等整段刪除，文案也改寫），這些翻譯多半已過時，且與新字串不一致；留著等於對使用者顯示「半新半舊」的混合介面，也沒有人能審稿。要恢復某個語言，請在該語言重新翻譯完整的 key 後再加回，並更新 `Tools/check_localization.py` 的 `ALLOWED_LANGS`。
- **語言解析**：`CFBundleDevelopmentRegion = en`、`CFBundleLocalizations = [en, zh-Hant]`（`boringNotch/Info.plist`）、xcstrings `sourceLanguage = en`、pbxproj `developmentRegion = en`／`knownRegions = (en, zh-Hant, Base)` 四處一致。系統語言為繁體中文（`zh-Hant`、`zh-Hant-TW`、`zh-Hant-HK`，後兩者會被 macOS 對應到 `zh-Hant.lproj`）時顯示繁中，其他語言（含簡體中文）顯示英文。
- **`CFBundleAllowMixedLocalizations = false`（M4 實測後改的）**：原本沿用上游的 `true`，離屏快照發現 zh-Hans 系統下 App 自己是英文，但第三方 KeyboardShortcuts 的錄製元件顯示簡體中文「设置快捷键」（它的資源 bundle 自帶多語系，`true` 讓它不受 App 語言清單限制）。改成 `false` 後：zh-Hans → 英文「Record Shortcut」；zh-Hant／zh-Hant-TW／zh-Hant-HK → 繁中「設定快速鍵」（該 bundle 的 `zh-TW.lproj`）。
- **key 慣例**：key 為英文原文（沿用上游），`en` 值省略時即 key 本身；格式類字串用 `Text(verbatim:)`，不進 xcstrings。零散的 AppKit／純字串位置（視窗標題、分頁標籤、Music 備援占位文字）改為 `String(localized:)`。
- **檢查**：`Tools/check_localization.py`（Python 3 標準庫）掃描原始碼中的在地化字面字串並比對 xcstrings，列出「用到但缺 zh-Hant」「孤兒 key」「非 en／zh-Hant 語言」「AppKit 直接字面字串」；加 `--stringsdata <DerivedData>` 可再與編譯器抽出的 `.stringsdata` 交叉比對（規則缺口會列出）。
- **離屏快照**：`ImageRenderer` 畫不出 AppKit 支撐的控制項（Form／Toggle／Picker 變佔位圖示），所以只有 Debug 建置內含 `SnapshotHarness`（`boringNotch/components/Settings/SnapshotHarness.swift`）：`-davidnookSnapshot YES -clipboardPaused YES -AppleLanguages (zh-Hant)` 啟動後以 `NSHostingView.cacheDisplay` 渲染真實的設定分頁，PNG 寫在沙盒容器暫存目錄後結束（在 `ClipboardService.start()` 之前，不會監看剪貼簿）。Release 不含此程式。

### 設定／About／onboarding（步驟 2）
- **onboarding 只說明、不觸發權限**：原本第二步「選擇音樂來源」會呼叫 `MusicManager.selectMediaController`，改為 `OnboardingOverviewView`（功能、權限與原因、唯一對外連線 lrclib.net）。這一頁不呼叫 AppleScript、剪貼簿、`CGRequestPostEventAccess`；按「繼續」只設 `firstLaunch = false` 與 `didChooseMediaController = true`（後者讓之後的備援提示可以顯示）。

## YouTube／瀏覽器影片來源支援（2026-10-06）

### 1. 問題
瀏覽器播 YouTube 時，MediaRemote 的 title 是**影片標題**（`周杰倫 Jay Chou【告白氣球 Balloon】Official MV`）、artist 常是**頻道名**
（唱片公司、`xxx - Topic`、VEVO、空白）、duration 是**影片長度**（含前奏、片尾，常比歌長）。原管線假設三者都是乾淨的曲目資料，
所以直接顯示「找不到歌詞」。

### 2. 來源怎麼判斷（已查證與未查證）
- 已查證（程式碼與二進位）：adapter 的 JSON 有 `bundleIdentifier` 與 `parentApplicationBundleIdentifier` 兩個欄位
  （`MediaRemoteAdapter.framework` 二進位內含這兩個字串；App 端 `NowPlayingPayload` 解碼，`NowPlayingStreamSupport.swift:257`）。
  `NowPlayingController.handleAdapterUpdate` 以 `parentApplicationBundleIdentifier ?? bundleIdentifier` 解出 `PlaybackState.bundleIdentifier`，
  `MusicManager` 每次狀態更新把它傳給 `LyricsService`（`LyricsTrack.sourceBundleID`）。
- **未驗證**：各瀏覽器實際回報的值（Safari 可能是 `com.apple.Safari` 或 `com.apple.WebKit.*` helper；Chrome 系可能是主程式或 `.helper`；網頁 App／PWA 是 `…app.<id>`）。
  所以比對採「`.` 邊界前綴」（`TrackTitleExtractor.isBrowserBundleID`），清單含 Safari／WebKit、Chrome／Chromium、Firefox、Arc／Dia、Edge、Brave、Opera、Vivaldi、Orion、DuckDuckGo、Yandex、Zen、Tor、SigmaOS。
- bundle id **已知且不是瀏覽器**（Apple Music、Spotify…）→ 一律乾淨來源，即使標題長得像影片標題。
  bundle id **未知（nil／空字串）** → 退回標題特徵（含 `【】｜|` 或 Official MV／Lyrics／歌詞／官方／HD 等裝飾詞片語）。

### 3. 管線
`LyricsRepository`（快取鍵＝**原始**曲目鍵，同一支影片不重複查；負快取同理）→ `VideoAwareLyricsFetcher` → `LrclibClient`。
- **乾淨來源**：`VideoAwareLyricsFetcher` 直通，請求與原本逐一相同（`testAppleMusicQueryProducesExactlyTheSameRequestsAsTheBareClient`）。
- **影片來源**：`TrackTitleExtractor`（純函式）產生有序候選 [(歌名, 歌手?)]，最多 6 筆；依序以 `isVideoDerived` 查詢交給 `LrclibClient`
  （先 `/api/get` 再 `/api/search`，沿用簡繁變體、節流、429／503 處理、多版本共識）；第一個有歌詞者勝出，全部沒有＝找不到。
  底層錯誤（網路、限流）原樣拋出，不當成「找不到」。
- **隱私不變**：唯一對外連線仍是 `lrclib.net`；送出的是**萃取後**的歌名與歌手（影片來源不帶 duration），不送原始影片標題與頻道名；沒有任何新 log。

### 4. 標題萃取規則（`TrackTitleExtractor`）
括號（`【】《》「」『』[]()`）、裝飾詞（Official MV／Music Video／Lyrics／歌詞／動態歌詞／完整版／HD／4K／官方／高音質／字幕…）、
分隔符（` - `、`–`、`—`、`|`、`｜`、`:`／`：`、` / `、CJK 間的 `-`）、`feat.`／`ft.`／`with` 客串（丟棄）、合作歌手（`&`、`,`、`、`、`x`：主歌手優先，全名次之）、
雙語（中文為主、英文為次候選）。頻道名去掉 ` - Topic`／VEVO／Official；唱片公司與歌詞頻道（Records、Music、Entertainment、唱片、音樂、Lyrics、Channel…）視為不可靠而丟棄，
可靠時只當弱提示（決定「A - B」的方向、補歌手）。方向不明時兩種方向都輸出（歌手在前優先）；猜錯只會查不到，不會放錯歌（見下節）。
Latin 裝飾詞只認片語，不吃單字 `video`／`audio`（`Video Games` 不被弄壞）。影片長度 > 15 分鐘（合輯、直播、整張專輯）不查。

### 5. 寧缺勿錯：長度與相符規則（`LyricsCandidatePicker`，只對影片查詢生效）
- **長度**（影片長度 − 歌長）：影片可比歌長最多 **60 秒**（前奏、片尾、對白）、比歌短最多 **5 秒**；歌手未知、只靠歌名時影片最多長 **20 秒**。
  非影片查詢仍是對稱 2 秒。排序規則不變（長度差小者優先 → 繁體優先 → 時間軸共識 …）。
- **歌名／歌手必須相符**（長度放寬後只有它把關）：折疊（簡繁、大小寫、標點不敏感）後相同，或較短者夠長且被包含
  （歌名較短者 ≥ 4 字；歌手 ≥ 2 字，容許合作歌手）。歌手未知時歌名要求完全相同。
- `/api/get` 對影片查詢不帶 duration（影片長度≠歌長；LRCLIB 的 get 會以它比對而 404）。

### 6. 測試
`TrackTitleExtractorTests`（43）、`LyricsCandidatePickerVideoTests`（16）、`VideoAwareLyricsFetcherTests`（17，stub transport 整合：
影片標題→正確 (歌名,歌手) 查詢→歌詞；第二候選／英文別名命中；影片過長、同名不同歌手、全部找不到→nil；網路錯誤不被吞；
快取與負快取鍵是原始曲目鍵；乾淨 Apple Music 請求與裸 client 完全相同）。Core 847 → 923。

### 7. 已知限制與沒有處理
- **時間軸對的是歌曲音訊、不是影片**：MV 開頭的前奏／對白／片頭會讓歌詞整體提早（歌詞比影片早走），需用面板的 ±0.5 秒按鈕調整（依原始曲目鍵記住）。
  影片比歌長多少無從得知，**不做自動補償**。
- 標題格式千變萬化，萃取是啟發式：沒收錄的裝飾詞、`歌手 歌名` 沒有分隔且頻道不可靠、歌名本身含 ` - ` 等會失敗（顯示「這首歌沒有歌詞」，不會放錯歌）。
- Live／Remix／Acoustic／Cover／Slowed 版本：裝飾詞被剝掉後查原曲，但長度與版本通常對不上，多半找不到（這是預期行為）。
- 同一頻道的混剪、歌單、整張專輯、直播、Podcast、非歌曲影片：> 15 分鐘直接不查；較短者靠相符規則擋。
- 未驗證：**真實的 YouTube 播放**（各瀏覽器實際回報的 bundle id、title／artist／duration 實際內容、LRCLIB 對各首歌的實際收錄）。

  仍在收合視窗（640×210，扣底部內縮 8）與涵蓋視窗（948×346）之內，`LyricsPillMetricsTests.testWorstCaseStaysInsideTheClosedAndCoveringWindows` 鎖定；最大寬度夾在 240–520（< 640）。
- **跑馬燈時間軸**（`LyricsMarquee`，純邏輯）：句子放得下（超出 < 0.5 pt）完全不捲；否則起點停頓 0.4 s → 勻速 → 句尾停頓。速度由「句子可用時間」推算：
  可用 ＝ 句長 − 0.4 − 0.6（句尾至少停 0.6 s）；倍率 1 用其中 80%，倍率越大越快，倍率 ≤ 0.8 用滿可用時間（不會為了「慢」而趕不上下一句）；速度夾在 24–140 pt/s：
  句子太長、時間太緊就加速到上限，再緊就來不及（接受的取捨）；時間很充裕也不會慢到爬。最後一句（沒有下一行）假設句長 6 s。捲完後畫面靜止。
- **換句**：`id` 交叉淡入＋3 pt 上移（時間沿用 `NotchMotion` 內容層淡入 0.30 s ÷ 速度）；膠囊底不淡、寬度平順變化。「減少動態」：不捲、0.2 s 純淡入淡出、單行尾端漸層截斷；關閉瀏海動畫則瞬間。
- **可見性狀態機**（`LyricsPillVisibility`）：功能開啟＋收合（且沒被隱藏／歡迎動畫／備援提示佔用）＋播放中＋歌詞已載入＋當前句非空才顯示。任一不成立立即淡出；唯一例外是暫停：其餘條件成立時維持 1.5 s 才淡出，暫停中不會新長出膠囊。
  載入中、失敗、查無歌詞、間奏（當前句空白）都不顯示。
- **資料**：沿用 `LyricsService`（`pillSample(at:)` 由同一份 `lines`／`timeline`／`offsetMs` 取得目前行與起訖），所以偏移調整、簡轉繁結果與展開面板一致；播放時鐘用 `MusicManager.estimatedPlaybackPosition`。
  不新增網路請求、不新增 log（log 不含歌詞）。
- **效能**：10 Hz 的 `TimelineView` 只在「功能開啟＋收合＋播放中＋歌詞已載入」時跑，其餘暫停（零逐幀成本）；逐幀（`.animation`）只在「這一句放不下、正在捲動」的那幾秒，捲完或靜止就停。
- **互動（hover／點擊）**：`ContentView` 的 `onHover`／`onTapGesture`／pan 手勢掛在 `mainLayout`（瀏海形體）上，膠囊在形體之外。最小改動：膠囊視覺 `allowsHitTesting(false)`（不吃點擊）；
  膠囊可見時另放一塊與膠囊同寬同高的透明區域，其 `onHover` 轉接同一個 `handleHover`、`onTapGesture` 轉接 `doOpen()`（條件與瀏海相同）。`handleHover(false)` 有離開延遲並會被下一次 `handleHover(true)` 取消，
  所以游標在瀏海與膠囊之間移動不會閃爍或誤收。pan／捲動手勢維持只掛在瀏海形體上，膠囊上不處理（不影響既有手勢）。
- **設定**：設定 → 媒體 → 歌詞：開關、與瀏海的距離、最大寬度、歌詞字級（11–16）、捲動速度（0.5×–2×）。所有值在使用處再夾一次（`LyricsPillMetrics.clamped*`）。
- **未驗證**：真機播放的手感與時間軸對音訊的準確度；有實體瀏海螢幕上膠囊的實際位置與下拉距離是否合手；無瀏海外接螢幕的瀏海底緣假設；hover／點擊轉接在真機上的行為（只讀程式碼推論）。
