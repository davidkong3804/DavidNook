# DavidNook 設計（2026-10-05，使用者已於對話中核准）

## 目標
macOS 瀏海工具，完全本機、無授權伺服器、永不過期。取代已失效的 NotchNook（專有軟體，不得複製其程式碼/素材/字串；只參考「行為」）。
只做：瀏海外觀與互動、剪貼簿歷史、動態歌詞（繁體中文正確性最優先）、播放控制（使用者所謂「歌詞點播」＝播放/暫停/上一首/下一首＋正確歌詞，不需獨立搜尋功能）。
不做：AI、帳號、雲端同步、遙測、自動更新。

## 架構
- `Packages/DavidNookCore`（Swift package，純邏輯，`swift test` 可跑）：LRC 解析與時間軸插值、歌詞候選挑選、簡/繁判斷與轉換、剪貼簿儲存規則。
- App 本體：fork 的 boring.notch，改名 DavidNook（bundle id、圖示、zh-Hant 為主要語言）。裁掉 Sparkle、NotificationWatcher、OTP 偵測、音訊擷取、鏡子等非指定模組與多餘權限；移除 `NSAllowsArbitraryLoads`、`network.server`。
- Now Playing：沿用 mediaremote-adapter，但由上游原始碼（v0.7.7）自行重建，不採用 repo 內預編譯二進位；啟動自檢（`test`），失敗退回 Music.app 備援。位置＝`elapsedTime + (now − timestamp) × playbackRate` 插值，不靠輪詢。

## 歌詞管線
1. 查詢：`/api/get`（原樣→s2t→t2s 三種寫法，帶 duration）；404 才 `/api/search`。必須自報 User-Agent；遵守 429 `Retry-After`；503 重試。
2. 過濾：instrumental、無 syncedLyrics、duration 差 >2s 皆剔除。排序：duration 差 → 原生繁體優先 → 首句時間貼近候選中位數 → id。
3. 清理：剝除檔頭中繼行（詞/曲/編曲/監製/OP/SP、`X - Y` 行，僅前 10 行且 <25s）、`[ti:]` 等 ID tag、尾端空時間戳行；處理 CRLF 與 `<mm:ss.xxx>` 行內標籤。
4. 簡繁判斷：統計全文「簡體專有字」與「繁體專有字」比例（排除 `麽`、`着`、`里后干发面台群於`）；無專有字→中性不轉；繁體專有字 ≤3%→簡體→轉換；簡體專有字 ≤3%→繁體→不轉（僅 t2tw 變體正規化）；其他→混合，逐行判斷。標題不可靠，用全文。歌名/歌手名不轉換顯示。
5. 轉換：先套覆寫表（如 发如雪→髮如雪、发端→髮端），再 OpenCC。
6. 偏移：以 title+artist+duration 為鍵，依曲目記住。
7. 顯示：約 5 行，當前行高亮，上下淡出。

## 剪貼簿
文字/圖片/檔案路徑；搜尋、釘選、暫停記錄、筆數與保留時間可設。略過 `org.nspasteboard.ConcealedType/TransientType/AutoGeneratedType`。只存本機（Application Support，0600 權限），不記錄內容到 log，提供「清除全部」。點選後寫回剪貼簿；已授權輔助使用時才自動貼上。

## 測試
先寫測試：LRC 解析與插值、簡轉繁黃金樣本（周杰伦→周杰倫、词→詞、软件→軟體〔慣用詞層開啟時〕、已是繁體不被轉壞）、剪貼簿過濾 concealed 型別與去重/釘選/上限。測試樣本用自編句子，**不放受版權保護的完整歌詞進公開 repo**。

## 里程碑
M1 瀏海殼（匯入上游、裁剪、改名、多螢幕）→ M2 Now Playing＋歌詞 → M3 剪貼簿 → M4 設定/繁中介面/圖示/README/NOTICES → M5 整合驗證（簡體來源華語、原生繁體、英文、無歌詞各一首，截圖；審稿 agent 檢查繁體正確性）後 push。

## 已知風險／未驗證
- **（M1 實測教訓）ad-hoc 簽章＋Hardened Runtime＋「連結」內嵌 framework → 啟動即崩潰**：dyld 報 `mapping process and mapped file (non-platform) have different Team IDs`（library validation）。編譯成功完全看不出來，只有實際啟動才會發現。正解不是關 Hardened Runtime，而是 adapter framework 只「嵌入」不「連結」（adapter 官方設計本來就是由 perl 載入）；app 原始碼沒有任何 `import MediaRemoteAdapter`。M2 自行重建 adapter 時維持此做法。
- **這台機器沒有實體瀏海螢幕**（M4 Pro 桌機：ASUS 外接螢幕＋一個虛擬/次要顯示器，`safeAreaInsets.top` 皆為 0），「有瀏海螢幕」的行為無法在本機實測，只能靠無瀏海（浮動瀏海）路徑與程式碼閱讀。
- **（M2 實測／核對）adapter 預設輸出的 `timestamp` 是 UTC、秒級解析度的字串**（`yyyy-MM-dd'T'HH:mm:ss'Z'`，小數秒被截掉），拿來當錨點會讓歌詞最多差 1 秒；改用 `stream --micros`（`timestampEpochMicros`／`elapsedTimeMicros`／`durationMicros`）。欄位格式依上游 README 與原始碼 v0.7.7 核對，**未用真實播放驗證**（此刻沒有播放，adapter `get`／`stream` 皆為空）。
- **（M2 實測）app 被 SIGTERM（pkill）時 adapter 的 perl 子行程會變孤兒**並一直活著（沒有輸出就不會因 SIGPIPE 結束）；已改為 SIGTERM 走正常終止流程。SIGKILL／當機仍可能留下孤兒，下次有輸出時會自行結束。
- **（M2）「純音樂」狀態**：UI 元件支援，但 LRCLIB 管線目前無法區分「純音樂」與「找不到」（Picker 會剔除 instrumental 候選、`LyricsFetching` 只回 nil），所以 app 目前對純音樂顯示「這首歌沒有歌詞」。要顯示「純音樂」需要擴充 Core 的回傳型別。
- **（M2）專輯名不送 LRCLIB**（來源資料很髒，只會降低命中率），也與設定頁揭露文字（曲名、歌手與長度）一致。
- adapter 依賴 Apple 私有行為（/usr/bin/perl entitlement），Apple 可能封掉；已有自檢與備援設計。
- 真實 Apple Music 播放、播放控制、歌詞時間軸 vs 實際音訊：未驗證（需使用者播放歌曲）。
- 背景輪詢 NSPasteboard 在 macOS 27 是否觸發隱私提示：未驗證。
- ad-hoc 簽章每次重建 cdhash 會變，TCC 授權可能要重授。
- 同 duration 的不同 LRCLIB 版本時間軸可能差 10 秒以上（實測旅行的意義），靠中位數挑選＋手動偏移緩解。
- 「台→臺」「了解→瞭解」屬風格問題，目前不處理，待使用者回饋。
