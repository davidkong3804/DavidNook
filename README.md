# DavidNook

macOS 瀏海工具：**完全本機、無伺服器、無遙測、無自動更新、無 AI、無帳號。**

[English README](README.en.md)

DavidNook 把螢幕頂端的瀏海（沒有瀏海的螢幕則是一條浮動的瀏海）變成一個小面板：顯示正在播放的歌曲與逐行同步歌詞，
並保存剪貼簿歷史。它是 [boring.notch](https://github.com/TheBoredTeam/boring.notch)（The Bored Team 與貢獻者，GPL-3.0）的
**GPL-3.0 衍生作品**（fork 自 tag `v2.8-rc.1`，完整 commit SHA `fb2643121741c6ba6102d5ef2b2c7a787f26fad1`，上游 git 歷史完整保留，
原始檔頭署名與 `Original source:` 註解皆未移除）。DavidNook 為獨立實作，**與 NotchNook 及其作者無關**。

## 功能

- **瀏海展開與 hover**：游標移到瀏海就展開、移開就收合；多螢幕、無瀏海螢幕皆可；可調高度、動畫、手勢與「精簡模式」。
- **Now Playing 與逐行歌詞**：顯示目前曲目、封面與進度；歌詞來自 [LRCLIB](https://lrclib.net)，依播放位置逐行高亮，
  可針對每首歌調整偏移。簡體來源的歌詞會自動轉成繁體（OpenCC 的 `s2tw` ＋自訂覆寫表；原生繁體歌詞不轉；
  「台灣慣用詞」轉換預設關閉，可在設定開啟）。在瀏覽器播放 YouTube 等影片時，會先從影片標題萃取歌名與歌手再查歌詞（見〈已知限制〉）。
- **收合瀏海的歌詞膠囊**：音樂播放時，瀏海正下方長出一顆細膠囊，目前這一句在裡面一句一句跑馬燈（放得下就靜止置中；放不下才捲動，並在下一句開始前捲完）。
  預設開；設定 → 媒體 可關閉，並調整下拉距離、最大寬度、字級與捲動速度。與展開面板共用同一份歌詞、偏移與簡轉繁結果；「減少動態」開啟時不捲動，改為尾端漸層截斷。
- **剪貼簿歷史**：記錄文字、圖片、檔案路徑；可搜尋、依類型篩選、釘選、點選貼回；筆數上限與保留時間可設，可暫停記錄。
  略過密碼管理員標記的項目（詳見〈隱私〉）。
- **影片（新，尚未在真機驗證）**：展開瀏海的「正在播放」面板裡，專輯封面右上有一顆低調的小按鈕；按下後用 macOS 的系統挑選器**挑一個視窗**，
  它的即時縮小畫面就會**取代專輯封面**顯示（橫向影片時封面槽會加寬，不擠壞歌名、控制列與歌詞；停止就回到封面）。
  **點一下影片＝釘選**：影片會在瀏海外面（收合狀態、瀏海正下方）長成一顆影片膠囊，再點一下取消。hover 影片時才出現「換視窗」「停止」，
  它們與釘選分開，不會互相觸發。只擷取你挑的那一個視窗、不擷取聲音、不顯示游標；沒挑視窗、面板不在畫面上時完全不擷取。
  設定 → 影片 可關閉整個功能，並調整「影片大小」（決定展開時封面槽可加寬的上限，以及釘選膠囊的大小）。
  **只看播放器（裁切）**：整個瀏覽器視窗（網址列、留言、推薦）不一定都要看。hover 影片按「裁切」會開一個獨立的小視窗，顯示那個視窗目前的畫面，
  拖曳框選要保留的區域（可再拖邊角微調、「重設為整個視窗」、「確定」「取消」）；確定後封面槽與釘選膠囊都只顯示框內，長寬比跟著裁切區域。
  也可按「自動偵測」：約 3 秒內比較畫面的變動，把變動最大的連通區域當作建議框（你可再微調；找不到明顯區域時只顯示說明，不亂框）。
  裁切會依來源 App 的 bundle id 記住（只存 bundle id 與相對視窗的比例矩形，不存視窗標題），下次挑同一個 App 的視窗會自動套用；hover 按鈕有「重設裁切」。
  裁切不影響 DRM 行為：受保護的來源仍然是黑畫面並顯示說明，本 App 不嘗試繞過。
  **桌面浮動視窗（自由的畫中畫）**：hover 封面槽的影片，按「浮動視窗」（`pip.enter` 圖示）就會在桌面開一個無邊框、不搶焦點的小視窗，顯示同一份即時畫面
  （共用同一條串流，不另開第二條擷取；有裁切就是裁切後的畫面）。**按住視窗任意處拖曳移動；拖四角縮放，長寬比鎖定、最小寬 160 pt、最大不超過所在螢幕可視範圍**；
  視窗浮在一般視窗之上，可出現在所有桌面空間與全螢幕 App 上方。滑鼠移上去才出現小控制列：關閉（✕）、收回瀏海（回到封面槽）、透明度（點一下在 100／80／60／40% 間循環）、釘選到瀏海（改成收合膠囊）；
  右鍵選單有相同動作，雙擊視窗＝收回瀏海。浮動視窗與收合膠囊同一時間只顯示一種（開浮動視窗時膠囊隱藏；點封面槽的影片仍是釘成膠囊並收掉浮動視窗）。
  只記住視窗的位置、寬度與透明度（UserDefaults 裡的幾個數字，不存任何內容或標題）；下次開啟會恢復，若上次的位置已不在任何螢幕內（例如拔掉外接螢幕），改放主螢幕右下角。多螢幕：視窗跟著你拖到的螢幕，不複製。
  DRM／受保護來源仍是黑畫面：浮動視窗**不會自動關閉**，而是在視窗內顯示簡短說明並保留關閉鈕（本 App 不嘗試繞過）。浮動視窗是你自己桌面上的視窗，所以截圖或螢幕分享可能會拍到它。
  **釘選膠囊（M-C）**：收合瀏海時，影片在瀏海正下方以圓角膠囊即時顯示，與歌詞膠囊垂直堆疊（歌詞在上、影片在下；沒有歌詞時影片上移，歌詞出現時平滑讓位）；
  展開瀏海時影片回到封面槽，外面的膠囊淡出，兩處不會同時重複。滑鼠移到膠囊上等同移到瀏海（點一下展開，取消釘選在展開後的封面槽裡做），hover 時右上角出現小圖釘。
  膠囊大小會被收合視窗的可用高度夾限（一般瀏海下方約 164 pt 高，16:9 約 291 pt 寬），超出就等比縮小，縮到寬小於 96 pt（例如很窄的直向影片）就不顯示。
- **播放控制**：上一首／播放暫停／下一首、隨機、重複、拖曳進度與音量；對「音樂」App 還有喜好項目；控制項欄位可自行排列。
- **繁體中文介面**：系統語言為繁體中文時顯示繁中，其他語言顯示英文。

## 隱私

- **資料只存在這台 Mac**：App 在沙盒內執行，資料放在容器內的 Application Support：
  - 歌詞快取：`DavidNook/Lyrics`（檔案權限 0600，可在 設定 → 媒體 清除）。
  - 剪貼簿歷史：`DavidNook/Clipboard`（目錄 0700、檔案 0600；設定 → 剪貼簿 可「清除未釘選」，或二次確認後「清除全部」，連同暫存圖片）。
  - 實際位置：`~/Library/Containers/io.github.davidkong3804.DavidNook/Data/Library/Application Support/DavidNook/`。
- **唯一的對外連線是 `lrclib.net`**（歌詞查詢），App 沒有其他網路用途。送出的內容只有：**曲名、歌手、長度（秒）**，
  以及一個自報身分的 `User-Agent: DavidNook/<版本> (專案網址)`（當然，伺服器會看到你的 IP 位址，這是任何網路請求都無法避免的）。
  影片來源（瀏覽器）送出的是**萃取後**的歌名與歌手，不送原始影片標題與頻道名，也不帶長度。
  **不會送出**：專輯名、剪貼簿內容、檔案路徑、任何識別碼或使用紀錄。要完全不連線，到 設定 → 媒體 關閉「顯示歌詞」。
- **沒有遙測、沒有更新伺服器**：不含 Sparkle 等自動更新元件，也沒有任何分析或當機回報。
- **不把內容寫進 log**：歌名、歌手、歌詞與剪貼簿內容都不會出現在 log 或除錯輸出。
- **剪貼簿**：略過標示為密碼或一次性內容的項目（`org.nspasteboard.ConcealedType`／`TransientType`／`AutoGeneratedType`）；
  單項上限文字 1 MB、圖片 20 MB。macOS 15.4 起，背景讀取剪貼簿會觸發系統的「從其他 App 貼上」提示；
  設為「每次詢問」或「拒絕」時，DavidNook 不會反覆讀取，而是在面板上提示你改成「允許」。
- **權限最小化**：沙盒＋網路 client（歌詞）＋ Apple 事件（僅限「音樂」App）。沒有檔案存取、相機或麥克風權限。
  沒有任何新的 entitlement：影片功能使用系統的視窗挑選器，不要求「整個螢幕」的錄製權限；Hardened Runtime 與 entitlements 與先前完全相同。
- **影片畫面**：畫面只存在記憶體（直接交給顯示層，隨串流佇列循環釋放）；**不存檔、不上傳、不快取、不截圖、不寫入剪貼簿**，沒有新增任何網路請求；
  不擷取聲音；log 只記狀態與錯誤碼，不含畫面內容、視窗標題或來源 App 名稱。App 每秒對畫面取樣一次平均亮度（只用來判斷是否全黑），取樣值不保留。
  macOS 擷取時會顯示系統的「正在錄製／分享」指示。
- **備份**：剪貼簿歷史與歌詞快取的資料夾都已排除於備份（`isExcludedFromBackup`），Time Machine 不會備份明文歷史，所以「清除全部」不會漏掉備份裡的舊副本。
- **自動貼上（實驗性、預設關）**：只在你明確開啟、已具備事件權限、且目前焦點不在「安全輸入欄位」（例如密碼欄）時才送出 ⌘V；焦點在安全輸入欄位時只複製、不貼上。

## 系統需求

- macOS 14（Sonoma）以上（`LSMinimumSystemVersion = 14.0`）；實際在 **macOS 27／Xcode 27** 上建置與驗證。
- 自行建置需要完整的 Xcode；不需要開發者帳號。
- **建置架構以產物為準：預設只建置本機架構。** 在 Apple Silicon 上建置的結果是 `arm64`，查證：

  ```sh
  lipo -archs build/DavidNook.app/Contents/MacOS/DavidNook
  # arm64
  ```

  內嵌的 mediaremote-adapter framework 是 `x86_64 arm64`，但 App 本體不是 Universal。Intel Mac 上建置只做過靜態推論，**未驗證**。

## 自行建置與 ad-hoc 簽章

DavidNook 以 **ad-hoc 簽章**（`codesign --sign -`）自行建置：沒有開發者帳號，因此**不能公證**（notarization 需要付費的
Apple Developer Program 憑證）。

```sh
# 1. 取得原始碼後，在專案根目錄建置（Release、ad-hoc；輸出 ./build/DavidNook.app，並印出簽章與 entitlements 摘要）
Tools/build_release.sh
#    需要乾淨建置時：Tools/build_release.sh --clean；其他選項見 Tools/build_release.sh --help

# 2. 安裝到 ~/Applications（只複製 App、移除複製後副本的 quarantine 屬性；不用 sudo、不改登入項目）
Tools/install.sh
#    指定其他資料夾：Tools/install.sh --dest "$HOME/Applications/試用"

# 3. 開啟
open "$HOME/Applications/DavidNook.app"
```

- 腳本在含空白的路徑下也能運作；缺少 Xcode 時會給出明確的錯誤訊息。`cmake` 只有 `--rebuild-adapter`（由上游原始碼重建
  mediaremote-adapter，見 `Tools/build_adapter.sh`）才需要。
- 建置完成後腳本會檢查：**Hardened Runtime 仍開啟**、主程式**沒有連結** `MediaRemoteAdapter.framework`（見〈疑難排解〉）。
- 純 Xcode 的做法（腳本內部做的事）：

  ```sh
  xcodebuild -project boringNotch.xcodeproj -scheme boringNotch -configuration Release -destination 'platform=macOS' \
    CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=YES -derivedDataPath build/DerivedData build
  ```

  （內部的 Xcode project／scheme／target 名稱仍沿用上游的 `boringNotch`，以便與上游合併；產品名稱與 bundle id 為
  `DavidNook`／`io.github.davidkong3804.DavidNook`。）
- 驗證簽章：`codesign --verify --deep --strict build/DavidNook.app`（沒有輸出即通過）。
- 純邏輯的 Swift package（LRC、簡繁轉換、剪貼簿規則、面板元件）可獨立測試：

  ```sh
  cd Packages/DavidNookCore && swift test
  ```

### Gatekeeper 與重新授權

- 在**本機自己建置**的 App 沒有 quarantine 屬性（沒有經過下載），通常不會被 Gatekeeper 擋。若 App 是從別台電腦、壓縮檔或網路
  取得而被擋下，請依系統提示操作；也可以直接在自己的 Mac 上重新建置，就不會被標記。
- **每次重新建置，ad-hoc 簽章的 cdhash 都會改變**，系統可能把它當成另一個 App：先前給過的授權（例如對「音樂」App 的自動化、
  輔助使用）可能需要重新授權；這是 ad-hoc 簽章的限制，不是 bug。

## 首次啟動與權限

第一次啟動會出現一個說明視窗：DavidNook 做什麼、會用到哪些權限與原因、唯一的對外連線。**這個視窗只說明，不會主動跳出任何
系統權限提示。**

| 權限 | 用途 | 何時被詢問 |
| --- | --- | --- |
| 自動化：「音樂」App | 系統的「正在播放」資訊無法使用時作為備援；以及「音樂」App 正在播放時，讀取／切換喜好項目與音量 | 第一次實際需要時，由 macOS 詢問 |
| 從其他 App 貼上（macOS 15.4+） | 剪貼簿歷史需要讀取你複製的內容 | 第一次讀取剪貼簿時（也就是複製東西之後）；之後到「系統設定 → 隱私權與安全性 → 從其他App貼上」可改 |
| 輔助使用／貼上事件 | **僅**「點選後自動貼上」（實驗性、預設關） | 只有在 設定 → 剪貼簿 開啟該選項並按「請求授權」時 |
| 螢幕錄製（影片） | 顯示你挑選的那一個視窗的即時畫面。**預期**走系統挑選器，由你每次選一個視窗，不需要預先授權整個螢幕 | 只有按下封面上的「擷取視窗」小按鈕才會用到；macOS 若要求授權，會在那時由系統詢問（**這部分行為尚未在真機驗證**） |

不想記錄剪貼簿：設定 → 剪貼簿 關閉「記錄剪貼簿歷史」，或隨時「暫停記錄」。不想用影片：設定 → 影片 關閉「在『正在播放』面板顯示挑選的視窗」。

## 疑難排解

- **App 一啟動就崩潰，dyld 訊息含 `mapping process and mapped file (non-platform) have different Team IDs`**：
  這是 library validation。ad-hoc 簽章沒有 Team ID，Hardened Runtime 會拒絕載入「連結」進主程式的 framework。
  正解是 **mediaremote-adapter 的 framework 只「嵌入」不「連結」**（上游設計本來就是由 `/usr/bin/perl` 載入它），
  原始碼中沒有 `import MediaRemoteAdapter`，也不得把它加入 target 的 Link Binary With Libraries。
  **不要靠關閉 Hardened Runtime 或加 `disable-library-validation` 解決**；`Tools/build_release.sh` 會在建置後檢查這兩件事。
  詳見 `Vendor/mediaremote-adapter/PROVENANCE.md`。
- **沒有歌詞**：確認 設定 → 媒體 的「顯示歌詞」已開、網路可連 `lrclib.net`；LRCLIB 沒有收錄的歌、純音樂都會顯示「這首歌沒有歌詞」。
  同一首歌的不同版本時間軸可能差很多，可用歌詞面板上的 ±0.5 秒按鈕調整偏移（會依曲目記住）。
- **「正在播放」無法使用**：設定 → 媒體 的來源區會說明原因，並自動改用「音樂」App 備援（需要自動化授權）。
- **剪貼簿面板說需要貼上權限**：到「系統設定 → 隱私權與安全性 → 從其他App貼上」把 DavidNook 設為「允許」（面板上有按鈕）。
- **沒有看到瀏海面板**：設定 → 一般 檢查顯示器設定；精簡模式沒有分頁列，因此看不到剪貼簿。
- **結束 App 後殘留 `perl` 行程**：以 SIGKILL 強制結束或當機時，adapter 的 perl 子行程可能殘留，下次有輸出時會自行結束；
  正常結束（選單列 → 結束，或 SIGTERM）不會殘留。

## 解除安裝

1. 若曾開啟「登入時啟動」，先到 設定 → 一般 關掉。
2. 結束 DavidNook，刪除 `DavidNook.app`（例如 `~/Applications/DavidNook.app`）。
3. 刪除資料（沙盒容器，內含歌詞快取、剪貼簿歷史與設定）：

   ```sh
   rm -rf ~/Library/Containers/io.github.davidkong3804.DavidNook
   ```

## 已知限制

- **瀏覽器播放 YouTube 等影片**：App 從影片標題（`【】《》`、`Official MV`、`歌手 - 歌名`、`feat.`、中英雙語…）與頻道名推測歌名和歌手，再去 LRCLIB 查；
  影片比歌長最多 60 秒、比歌短最多 5 秒才接受，且歌名與歌手必須與 LRCLIB 的紀錄相符，**寧可顯示「這首歌沒有歌詞」也不放錯歌**。已知限制：
  歌詞時間軸對的是歌曲音訊，MV 的前奏／對白會讓歌詞整體提早，需自行用 ±0.5 秒按鈕調整；標題格式千變萬化，萃取是啟發式，認不出來就查不到；
  Live／Remix／Cover 版本、超過 15 分鐘的影片（合輯、直播）多半找不到；唱片公司頻道不當歌手。只有瀏覽器來源（依 bundle id，或標題特徵）才會這樣處理，
  Apple Music 等來源完全不變。**尚未用真實 YouTube 播放驗證**（各瀏覽器實際回報的來源 bundle id 與欄位內容以實測為準）。
- **純音樂**目前顯示為「這首歌沒有歌詞」：LRCLIB 管線尚無法區分「純音樂」與「找不到」。
- **風格問題**：歌詞簡轉繁後的「台→臺」「了解→瞭解」等用字風格不處理；「髮／發」等一字對多字的歧義，
  靠覆寫表處理常見詞（如「发如雪」→「髮如雪」），邊界情況仍可能轉錯。
- **自動貼上為實驗性**：App 在沙盒內，能否送出 ⌘V 取決於系統接受與否，尚未在所有 macOS 版本驗證；沒有授權時只會把項目放回剪貼簿。
- **沒有在有瀏海的實體螢幕上實測**（開發機是無瀏海的桌機）；有瀏海螢幕的行為只靠程式碼閱讀與無瀏海路徑推論。
- **歌詞膠囊只做過離屏渲染與單元測試**：沒有在真機實際播放、也沒有在有實體瀏海的螢幕上確認膠囊的實際位置與手感。有實體瀏海時，膠囊畫在螢幕顯示區域內，會佔用瀏海下方一點空間（距離可在設定調整，預設 6 pt）；
  膠囊顯示時，滑鼠移到膠囊上等同移到瀏海（會觸發 hover 展開與點擊展開），但膠囊上不支援滑動手勢。
- **播放器相容性以實測為準**：真實的 Apple Music／Spotify／瀏覽器播放、播放控制與歌詞時間軸對音訊的準確度，需要實際播放才能驗證，
  尚未完整驗證；「正在播放」依賴 Apple 的私有行為，未來的 macOS 版本可能改變（已有備援）。
- 剪貼簿端到端（複製→記錄→點選貼回）、輸入法組字下的搜尋欄、多螢幕與精簡模式，未在真機完整驗證。
- **影片功能尚未在真機驗證**：開發時只做過一次最小的實機試驗（沙盒＋ad-hoc＋Hardened Runtime 下，系統挑選器能彈出、串流約 20 fps／480 寬、畫面非黑），
  其餘（本功能的完整操作手感、各瀏覽器視窗與畫中畫視窗、其他桌面空間的視窗、視窗最小化／關閉的偵測、重新建置後授權是否失效、CPU／記憶體實測）都**未驗證**。
- **受內容保護（DRM）的來源不會顯示**（例如 Netflix、Apple TV）：這是系統的保護機制，本 App **不會也不應**嘗試繞過。
  偵測到畫面持續全黑（連續約 3 秒平均亮度低於 2/255）時，會顯示「這個來源受內容保護」的說明；建議改用來源本身的畫中畫，或沒有保護的來源（YouTube、本機影片）。
  這個判斷是啟發式：真的很暗的畫面（例如長時間全黑的場景）可能被誤判，畫面一亮就會自動恢復。
- **影片的其他限制**：每次啟動 App 都要重新挑選視窗（挑選結果不跨重啟保存）；一次只顯示一個視窗；不轉送點擊、不能操作來源視窗；視窗最小化時畫面會暫停；
  封面槽只在版面放得下時加寬（最小的面板尺寸下維持方形，影片等比縮小；說明文字也會精簡成只剩標題與按鈕，完整說明放在提示氣泡）；
  釘選在串流結束（停止、來源視窗關閉、錯誤）或偵測到黑畫面（疑似受保護）時會自動取消，重新啟動 App 也不會殘留。
- **裁切的已知限制**：**裁切（`sourceRect`）未在真機驗證**，SDK 標頭沒有明說視窗擷取時 `sourceRect` 的原點，目前假設相對視窗、左上為原點、單位 pt，若實測方向不對需要修正；
  裁切啟用期間不追蹤來源視窗被縮放（框內畫面無法得知視窗大小），縮放後請重新裁切或重設；macOS 15.2 以下取不到來源 App 的 bundle id，裁切只套用於本次串流、不會被記住；
  自動偵測是啟發式：影片暫停／靜止時偵測不到、整頁都在動（捲動）或全螢幕會回「找不到」、旁邊有大面積動畫廣告可能框到別處，請手動微調；編輯裁切時會暫時串流整個視窗（較大尺寸），確定後才縮回裁切區域；黑畫面偵測只看裁切區域。
- **浮動視窗的已知限制**：**拖曳／縮放手感、多螢幕、全螢幕 App 上方與多個桌面空間的實際顯示、GPU／CPU 負擔皆未在真機驗證**（只有純邏輯測試與離屏渲染）；
  視窗內容為純 AppKit（不使用 SwiftUI NSHostingView，避免視窗改大小時的版面更新迴圈）；「收回瀏海」只關閉浮動視窗（展開瀏海後影片在封面槽），不會自動展開瀏海；
  浮動視窗開著時串流持續進行（約 20 fps），不受瀏海收合影響；來源畫面比例改變（裁切、來源視窗縮放）時視窗寬度不變、高度跟著變。
- **釘選膠囊的已知限制（M-C）**：釘選期間收合瀏海也會持續串流（約 20 fps、不擷取聲音），**會持續吃一點 GPU／CPU，實際用量未量測**；
  DRM／黑畫面來源不會顯示膠囊（偵測到就自動取消釘選，膠囊淡出，不顯示黑塊）；多螢幕時每個螢幕的收合瀏海都會顯示同一顆膠囊（與歌詞膠囊相同做法）；
  **尚未在有實體瀏海的螢幕上驗證**，也未實測膠囊的手感與動畫。
